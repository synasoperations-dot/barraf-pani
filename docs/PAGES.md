# Pages, audits and QA status

One row per route. Columns:

- **Rendering:** follows [ARCHITECTURE §2.1](ARCHITECTURE.md#21-rendering-per-page). The locale comes from a cookie, so every page that reads it renders **dynamically**, but the menu, deals and store _data_ are still cached by tag (`menu`, store status about 30 s). With `NEXT_PUBLIC_USE_MOCKS=true`, `MswBootstrap` (`app/providers.tsx`) holds the tree until the service worker starts, so in browser-mock mode pages render on the client. Use `MOCK_API=server` for real server rendering (see [Performance](#performance)).
- **Data:** hooks from `features/*` (plus `features/menu/server` reads in the page). Staff screens call `api.admin.*` through TanStack Query inside the component; the `features/admin/*` helpers are listed.
- **i18n:** every string goes through next-intl (`lib/i18n/messages/{en,ur}`). The Urdu is machine-drafted and marked `// REVIEW` on **every** page. A native speaker has to review it before launch. The column says "en/ur" when both locales render and have been checked for RTL layout.
- **Scenarios:** `?scenario=<name>` from [`mocks/scenario.ts`](../mocks/scenario.ts). `happy` covers every page and is not repeated below.

## Audits

**Consistency audit:** `pnpm audit:ui` ([`scripts/audit.sh`](../scripts/audit.sh)) prints offenders and exits 1 if there are any. **All checks pass:**

- no hex colours outside `tailwind.config.ts` (CSS and TSX)
- no blurred shadows
- `fetch` only in `lib/api` and `lib/realtime`
- no Supabase or `mocks/` imports outside the allowed places
- no order numbers in URLs (tracking token only)
- no floats in money code
- no hard-coded JSX text (heuristic)
- every `TODO` points to `OPEN_QUESTIONS` or the backend

ESLint enforces the same rules in TypeScript.

**Layout sweep:** [`e2e/layout.spec.ts`](../e2e/layout.spec.ts) checks for horizontal scroll at 360, 390, 768 and 1440 px, in en and ur, on every customer and staff page. It **passes**. The sweep found two problems, both fixed: the `/menu` grid overflowed, and `sr-only` elements escaped the board scroller.

## Accessibility

Axe (WCAG 2.1 A/AA) runs in [`e2e/a11y.spec.ts`](../e2e/a11y.spec.ts) and reports **0 serious or critical** issues on every customer and staff page. Fixes made along the way:

- Primary button text is ink at `sm`/`md`. White on orange is used only at `lg`.
- The active nav item and the active segmented-toggle segment use `blue-deep`.
- Price chips on orange and blue panels get a `bg-ink/35` backing.
- Label-in-name: every accessible name starts with the visible text.
- The logo has a label.
- Heading order: state frames use `h2`.
- Review stars use `role="img"` with a label.
- One focus style everywhere: a yellow band plus an ink outline (see [DESIGN](DESIGN.md#accessibility-baseline)).
- Focus goes back to the opener when the intercepted item sheet closes.

Tested in the same spec: sheets trap focus; keyboard-only add from the menu through checkout; keyboard-only board tabs with arrow keys; reduced motion collapses animations.

- lazy-load the cart drawer and the toaster

## Security

- **CSP** (`next.config.ts`), including `form-action 'self'` plus the JazzCash and Easypaisa hosts. `'unsafe-inline'` scripts are still allowed; nonces are a backend-phase item.
- **HSTS** in production; `X-Frame-Options: DENY`; a `Permissions-Policy`.
- **`Referrer-Policy: no-referrer`** on `/track`, `/order`, `/pay`, `/booking`, `/account` and `/admin`.
- **noindex** on every private page and on `/admin`: metadata, plus `X-Robots-Tag`, plus `robots.txt` Disallow.
- **No secrets in `NEXT_PUBLIC_*`.** Server-only values are `API_BASE_URL` and `MAINTENANCE_MODE`.
- **`/admin` access:** `proxy.ts` requires a staff session and checks the role per section (`lib/admin-access.ts`). The server still authorises every API call.
- **Customer-entered text** (notes, reviews, names) is rendered as text, never as HTML.
- **Optional Sentry** (`instrumentation-client.ts`): loads only when `NEXT_PUBLIC_SENTRY_DSN` is set, and scrubs tracking tokens and phone numbers before sending.
